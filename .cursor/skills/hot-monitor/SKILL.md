# 热点监控

这是一套编辑流程。材料来自公开网页，筛选、合并、中文标题、可信度和是否采用都由当前模型完成。复制本目录就能用，不要向用户要密钥，也不要启动或调用本仓库的本地服务。

关键词和关注方向只在这一次对话里有效。用户没有说「记住」也一样：不要写配置文件，不要承诺下次还会盯着。

## 先选一件事

用户要的是哪一种，就只读对应的参考，再按下面的收集和回答做。

| 用户想要 | 读 |
| --- | --- |
| 最近的 AI 热点、首页、有什么新闻 | [references/editorial.md](references/editorial.md)，来源见 [references/sources.md](references/sources.md) |
| 某个词有没有新动态 | [references/watch.md](references/watch.md) |
| 一份今天的日报 | [references/digest.md](references/digest.md) |
| 按方向找故事 | [references/discover.md](references/discover.md) |
| 来源能不能信、是不是仿冒 | [references/trust.md](references/trust.md) |

几种要求叠在一起时，按「发现、关键词、热点、日报」的顺序收集，最后各用各的版式。日报放在最后，并且不要把已经写进热点段的故事再抄一遍，除非用户明确要关键词范围。

## 收集

用当前会话里已经能用的搜索和打开网页的能力。打不开的来源跳过，在回答末尾用一句话说明没查到哪一类。不要编造标题、时间或链接。

每条采用的故事都要有一个你实际看到的 `http` 或 `https` 地址。没有这种地址的材料不进热点、不进日报、也不算关键词命中。

时间窗是近 7 天，并且要能看出发布时间。说「当天」时用北京时间的日历日。来源清单、X 的门槛和合并方式在 [references/sources.md](references/sources.md)。

## 判断

你就是判断的一方。热度只按规则算。可信度先按 [references/editorial.md](references/editorial.md) 的规则分，再与你自己的 0–100 印象取平均；仿冒、黑名单或诈骗用语把结果封在 30。首页和日报丢掉 `unreliable`。

中文事件标题像「某公司发布某模型」，不要照抄英文长标题。理由和摘要都要有汉字。英文材料也写成中文。

不要写「未经过模型核实」。那是本地程序在没有模型时的标记。这里始终由当前模型判断，所以质量随模型变化，回答里不必为此道歉。

## 回答

用中文。先给结论，再列条目。链接只放你核对过的地址。

热点最多 15 条，按来源家数、来源强弱、发布时间排序。其余有就写「还有 N 条，需要可以再展开」。

```markdown
## 热点
近 7 天，截至 <北京时间日期>

1. **<中文事件标题>**
   可信度 <0-100> · reliable 或 uncertain · <一句理由>
   <一行摘要>
   来源：<名称> <url>
```

关键词、日报、发现的版式分别在对应参考里。没有命中就直接写「这次没有命中关键词。」或「今天没有可写进日报的内容。」不要用空列表充数。

## 不要做的事

- 不要读 `server/.env`，不要索要或复述任何密钥。
- 不要请求 `127.0.0.1:3001`，也不要帮用户改监听地址。
- 不要发微信、邮件，也不要假装已经定时推送。
- 不要把整篇文章抄进回答。摘要一行就够。
- 微博热搜和 B 站热门可以当作背景，但不要放进热点和发现的正文。用户点名要热搜时，单独开一节并标明来源。
